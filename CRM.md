# Визуальный редактор страниц

Страницы кейсов правятся прямо на самой странице: открыли, щёлкнули по
заголовку, набрали новый. Отдельной формы с полями больше нет.

## Как открыть

К адресу страницы добавьте `?crm`:

```
case-medsi.html?crm
```

Прежний вход `#crm` тоже работает. Без этого адреса скрипт редактора
выходит на первой строке и на публичной странице не делает ничего.

## Что можно делать

| Действие | Как |
| --- | --- |
| Текст | Щелчок по тексту. Панель над ним: жирный, курсив, подчёркивание, ссылка, размер, выравнивание |
| Размер текста | Только ступени сайта: надзаголовок, мелкий, обычный, подзаголовок, заголовок кейса, заголовок раздела |
| Картинка | Щелчок по картинке → «Заменить» (файл с диска) или «Медиатека» (что уже есть в проекте). Ширина — боковыми ручками или кнопками − / + |
| Новый блок | Подведите курсор к границе между блоками → «+ Добавить блок» → выбор типа |
| Порядок | Выберите блок и тяните за ⠿. Подблок можно перенести в другую секцию |
| Устройства | Десктоп / Планшет / Телефон в верхней панели |
| Отмена | Ctrl+Z, возврат Ctrl+Shift+Z, кнопки ↶ ↷ |
| Сохранение | Автоматически в браузер. «Экспорт HTML» собирает готовый файл страницы |

Правки живут в браузере (`localStorage`). Чтобы они попали на сайт,
нажмите «Экспорт HTML», положите скачанный файл вместо текущего и
запушьте. Загруженные с диска картинки встраиваются прямо в файл —
для готового сайта лучше положить их в `assets/` и указать путь.

## Как устроено

**Один редактор на все страницы.** Раньше CRM была скопирована в каждую
из шести страниц. Теперь код лежит в `assets/crm-editor.js`, а страница
отдаёт ему мост:

```js
window.CRM_HOST = {
  id: CURRENT,
  get T(){ return T; },        // данные страницы
  get IMG(){ return IMG; },
  get L(){ return L; },        // текущий язык
  get render(){ return render; },
  set render(f){ render = f; },
  caps: { ... }                // что умеет рендер этой страницы
};
```

**Рендер не переписан.** Редактор оборачивает `render()`: сначала
работает обычная отрисовка страницы, потом редактор навешивает на
готовый DOM атрибуты `data-crm-p` с путём в данных — например
`["blocks",3,"subs",1,"note"]`. Поэтому то, что видно в редакторе, —
это буквально публичная страница, а не её копия.

**Данные прежние.** Тот же объект `T` с ветками `ru`/`en`, тот же
черновик `crm:<id>` формата `{IMG,T}`, тот же экспорт через маркеры
`/*CRM_T_S*/ … /*CRM_T_E*/`. Старые черновики открываются как есть.

**Языки.** Текст правится для текущего языка. Структура — добавление,
удаление, дублирование, перенос — применяется сразу к `ru` и `en`,
иначе ветки разъезжаются. Если массивы в языках уже разной длины
(так сейчас с `duties`), правится только текущий язык.

**Форматирование** хранится как HTML внутри тех же строк, что и раньше
(`<b>`, `<br>`, `<span style="font-size:var(--h3)">`). Никаких новых
полей в данных для этого не понадобилось. Чужая разметка при вставке
вычищается: остаются только `b/i/u/em/strong/br/a/span/sup/sub`.

**Внешний вид.** Интерфейс редактора собран из того, что уже есть в
проекте: токены `--accent`, `--line`, `--surface`, `--ink`, `--muted`,
`--sel`, шкала `--h1…--eyebrow`, шрифт `--sans`, компоненты `.card`,
`.chip`, `.segmented`, радиусы 7 / 10 / 14 / 20px. Новых цветов,
шрифтов и размеров не заведено.

**Рамки и панели** живут только в режиме редактирования (класс
`crm-on` на `<html>`) и в экспортированный файл не попадают.

## Что было доработано в самих страницах

Минимум, только чтобы редактору было чем управлять:

1. Вырезана старая встроенная CRM (панель с полями), добавлен мост
   `CRM_HOST` и подключение `assets/crm-editor.js`.
2. На `loko`, `rwb`, `vtb`, `zephyr` включён вывод `s.imgs` (ряд
   картинок) вместе с лайтбоксом — код и стили взяты с `medsi`
   один в один. Раньше кнопка «добавить картинку» там была, а рендера
   не было, и картинка просто не появлялась.
3. У картинки появилась необязательная ширина `im.w`.
4. Разделитель `s.sep` рисуется существующим компонентом `.head-sep`.

Публичный вид страниц при этом не изменился: новые ветки рендера
включаются только при наличии данных, которых сейчас нет. Это
проверено — отрисовка всех шести страниц совпадает с исходной
посимвольно.

## Проверка

`build/test.js` прогоняет редактор в jsdom настоящими событиями DOM:
101 проверка, включая совпадение публичной отрисовки с исходной,
правку текста, зеркальность структурных правок по языкам,
перетаскивание, Undo/Redo, экспорт и повторное открытие
выгруженного файла.

```
node build/test.js
```

## Чего сознательно нет

В проекте нет компонентов кнопки-CTA и видео, поэтому таких типов
блоков в наборе тоже нет: добавить их — значит придумать новый дизайн.
Если они понадобятся, сначала стоит завести компонент в самой
дизайн-системе сайта, и редактор подхватит его как остальные.

Ширина колонок в `.cols` не настраивается: сетка авто-адаптивная
(`auto-fit, minmax(...)`), и ручная ширина сломала бы её на узких
экранах.

# Второй заход: что изменилось

## Меню больше не отдельный список

Раньше названия пунктов меню лежали в массиве `PROJECTS`, продублированном
во всех семи файлах. Заголовок блока и пункт меню были разными местами,
поэтому переименование блока до меню не доходило.

Теперь:

* **Подменю кейса собирается из блоков самой страницы.** Переименовали
  блок — переименовался пункт. Подменю появляется, когда блоков больше
  одного (на незаполненных страницах его по-прежнему нет).
* **Список проектов уехал в `assets/site.js`** — один файл на весь сайт.
  Правите название проекта на любой странице, экспортируете `site.js`,
  и меню меняется везде.

В меню строка проекта сначала выбирается щелчком, и только вторым
щелчком правится название: иначе не отличить «переименовать» от «перейти».
Для перехода на панели есть кнопка «Открыть страницу».

## Главная страница правится так же, как кейсы

`index.html` подключён к редактору. Правятся: заголовок и текст о себе,
места работы вместе с их пунктами, образование, навыки, личные карточки,
подписи разделов.

Данные там устроены иначе — язык лежит у каждого поля (`{ru,en}`), а не
сверху. Поэтому путь к данным в редакторе теперь умеет обе схемы:

```
["blocks",2,"note"]                   → T.ru.blocks[2].note   (кейс)
["EXPERIENCE","list",0,"role","$L"]   → EXPERIENCE[0].role.ru (главная)
```

`$L` означает «текущий язык». Структурные правки повторяются во всех
языках только там, где `$L` в пути есть; на главной каждый элемент и так
хранит оба языка, и повторять нечего.

## Панель уровней

Панель стала двухэтажной. Сверху цепочка `Раздел › Блок › Пункт › Текст`,
щелчок переключает уровень. Снизу действия выбранного уровня.

Отсюда же удаляется отдельная сущность: выбрали «Пункт» — получили
«Удалить», «Дублировать», «+ ещё такой же». Удаляется именно пункт.

## Перенос и отступы

* **«В секцию ▾»** у блока и **«Под раздел ▾»** у секции — перенос
  выбором из списка, без перетаскивания через всю страницу.
  Перетаскивание тоже осталось.
* **«Отступ ▾»** — расстояние сверху: без отступа, малый, средний,
  большой, как между кейсами. Значения взяты из ритма, который уже есть
  в вёрстке (16 / 40 / 80 / 120), новых не заведено.

## Перевод

Кнопка «Перевод» собирает все места, где английского нет или он совпал с
русским. Можно вписать перевод рядом, а можно «Скопировать для перевода»
→ перевести где угодно → «Вставить перевод» списком в том же порядке.

## Языки могут разойтись — теперь это видно

Если структура `ru` и `en` разъехалась (блок есть в одном языке и нет в
другом), зеркальные правки для этой ветки перестают работать. Раньше это
происходило молча и накапливалось.

Теперь расхождение показано в верхней панели, а «Перевод» сначала
предлагает **выровнять структуру**: недостающие элементы копируются из
русского, чтобы их было что переводить. Существующие английские тексты не
трогаются, лишнее не удаляется.

В присланных данных нашлось одно такое расхождение — блок «Макеты» с
картинкой, добавленный только в русскую версию.

## Экспорт

Кнопка «Экспорт» открывает окно:

* **Скачать страницу** — как раньше.
* **Скачать assets/site.js** — общий список проектов, нужен только если
  правили левое меню.
* **Вынести картинки в отдельные файлы** — появляется, если в страницу
  вшиты картинки целиком. В присланном `case-sberpravo.html` такая одна,
  из-за неё файл вырос с 76 КБ до 286 КБ.

## Проверка

`build/test2.js` — 150 проверок в jsdom настоящими событиями DOM.

Отдельно нашлась ошибка в самом прогоне: код редактора подставлялся в
страницу строкой замены, а в ней `$$` и `$&` значат не то, что написано,
и код портился. Из-за этого прошлые прогоны проверяли слегка искажённый
редактор. Исправлено, все проверки перезапущены.

# Четвёртый заход

## Маркер списка

Звёздочка стояла выше середины строки: у неё была своя высота строки
(`line-height:1.55` при кегле `.85rem`), меньше, чем у текста пункта.
Теперь маркер занимает коробку ростом ровно в одну строку текста и
центрируется в ней:

```css
.points li::before{
  content:"✦";
  position:absolute; left:0; top:0;
  font-size:.85rem;
  line-height:1;
  display:flex; align-items:center;
  height:calc(var(--text) * 1.6);   /* высота одной строки пункта */
}
```

`1.6` — это `line-height` страницы. У списка «в строку» (`.points.inline`)
своя высота строки, поэтому там `1.45`. Правило поправлено во всех
местах, где рисуется звёздочка: `.points`, `.points.cross`,
`.points.inline` и `.duties` — на всех семи страницах.

## Medsi

Порядок в «Обязанностях» перевёрнут: сначала блок про работу, потом
сервисы.

* «Как Lead UX/UI Designer» → **«Обязанности и достижения как Lead
  UX/UI Designer»**, блок поднят наверх;
* «Сервисы, над которыми я работал:» вместе со своими четырьмя
  пунктами опущен вниз.

## СберПраво

* Абзац про платформы и роли больше не пункт списка — он перенесён в
  описание кейса (`desc`), где выводится обычным `.exp-summary` без
  маркера. Отдельного CSS для этого не понадобилось: в проекте уже есть
  стиль для вводного абзаца.
* Блоки поменялись местами и переименованы: сначала **«Обязанности и
  достижения как Lead UX/UI Designer»**, ниже **«Обязанности и
  достижения как Senior UX/UI Designer»**.

## Английская версия

Заодно убраны повторы, которые появились в английских обязанностях при
переносе правок в прошлый раз: в Medsi и СберПраво часть пунктов была
переведена дважды и осталась в списке в двух вариантах. Английские
списки заново собраны по структуре русских, добавлены описания четырёх
сервисов Medsi, которых в английской версии не было.

## Черновик старше файла

Правки живут в браузере (`localStorage`), а не в файле. Раньше редактор
применял черновик молча — и если файл страницы успели обновить, старый
черновик перекрывал свежие правки. Со стороны это выглядело так:
публичная страница новая, а `?crm` показывает старое.

Теперь черновик помнит, от какой версии файла он отпочковался. Если файл
с тех пор изменился, редактор при открытии спрашивает:

* **Взять из файла** — черновик удаляется, работаем с тем, что в проекте;
* **Оставить черновик** — применяем сохранённое в браузере.

Ответ запоминается: повторно тот же вопрос не задаётся.

Если сомневаетесь — выбирайте «Взять из файла».

Кнопка **«Взять из файлов»** в верхней панели делает то же самое в любой
момент: удаляет всё, что сохранено только в браузере (и содержимое
страницы, и названия проектов в меню), и показывает то, что лежит в
файлах проекта.

# Картинки: как добавлять

Присылать картинки куда-либо не нужно. Порядок такой:

1. **Кладёте файл в папку `assets`** в репозитории. На github.com:
   откройте папку `assets` → **Add file → Upload files** → перетащите
   сразу сколько угодно файлов → **Commit changes**.
2. **Открываете страницу с `?crm`**, щёлкаете по картинке (или добавляете
   блок «Изображение») → **«Медиатека»**.
3. Файл уже в списке — щёлкаете по нему.
4. **«Экспорт» → «Скачать страницу»**, кладёте файл в проект вместо
   текущего, пушите.

Медиатека сама читает содержимое папки `assets` через открытый API
GitHub, поэтому загружать картинку второй раз через редактор не нужно —
достаточно того, что она лежит в репозитории. Список обновляется раз в
час, кнопка **«Обновить список»** перечитывает его сразу (нажмите её
после того, как запушили новые файлы).

Локально (открытый с диска файл) список получить неоткуда — там впишите
путь руками в поле «Путь в проекте или адрес картинки», например
`assets/sberpravo-screens.png`.

## Чего лучше не делать

Кнопка «Загрузить файл с диска» вшивает картинку прямо в HTML в виде
текста. Страница от этого распухает в разы: одна такая картинка в
`case-sberpravo.html` весит 184 КБ при том, что вся страница без неё —
около 90 КБ. Пользуйтесь ей только для быстрой примерки.

Уже вшитые картинки вынимаются кнопкой **«Вынести картинки в отдельные
файлы»** в окне экспорта: каждая скачается отдельным файлом, вы кладёте
их в `assets`, а в странице остаются короткие пути.

## Что присылать на доработку

Картинки не нужны — только код. Достаточно семи `*.html`,
`assets/crm-editor.js` и `assets/site.js`. Папку `assets` с картинками
из архива можно удалить: страницы ссылаются на картинки путями, и для
правки текста или разметки сами файлы не требуются.

## Имена файлов

Удобно держать общий шаблон `<страница>-<что>.<расширение>`, как уже
сделано: `sberpravo-menu-cards.png`, `medsi-booking.png`. Тогда в
медиатеке файлы нужной страницы стоят рядом.
